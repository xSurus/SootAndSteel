# B2.3 in-game HUD port plan

Branch `port/ui-hud` (from main 4554310). `Src/` is read-only. Follow `Unity/CONVENTIONS.md` and the handoff testing rules (C# 9, netstandard2.1, never `-quit` with `-runTests`, one Unity process at a time, `git add Unity/Assets`, commit per task).
Slice: `GameplayHud` (train progress track with moving train marker, goal marker, enemy dots, speedometer needle, temperature frost overlay) and the four `IngameHUD` components. Screen space only.

## What the Src HUD really is

Read from `Src/UI/GameplayHud.cs`, `Src/Components/IngameHUD/*` and the four `.gucx` files (layout numbers, not the `.Generated.cs`):

- The "enemy dots" are not live enemies. `GameplayHud.EnsureEnemyDots` puts one dot per `LevelDefinition.SpawnEvents` entry on the distance track at `spawn.Distance / levelDistance`. So no enemy runtime seam is needed, only the `LevelDefinition` that `LevelRuntime.Definition` already exposes.
- The HUD does not show wall health, so `ShootHoleWallRuntime` is not touched. Temperature only drives the frost overlay (three full-screen textures blended by `1 - temperature / maxTemperature`).
- There is no dial face sprite in the speedometer. The dial is drawn into `GaugeDistance.png` (4846 x 1000, shown at 20 percent, so 969.2 x 200). The needle is `GaugeHand.png` inside a rotating container.
- `WorldUiManager` is the world-anchored tooltip manager. B2.2 already ported all of it (`TooltipLayer`, `TooltipLayout`, `TooltipModel`, `TooltipInteractions`). Nothing of it belongs to the HUD, so this slice adds nothing from it.
- `CurrencyDisplay` and `ToolTip` are not used by the HUD.

## Design

Core (engine-free, EditMode tests, goldens from the Src formulas evaluated by a script):
- `Gamelab.UI.HudMath`: `DistanceRatio(distance, levelDistance)` (level distance floored at 1, distance floored at 0, clamped 0..1), `TrackTravelRange(trackWidth)` (0 when width <= 1, else max(0, width - 48)), `SpeedRatio(actual, maxSpeed)` (max speed floored at 1, clamped), `NeedleDegrees(speed)` (600 km/h scale, lerp 115.7099 to -119.0546, normalised to 0..360, so 0 gives 115.7099, 300 gives 358.32765, 600 gives 240.9454), `FrostOpacity(layer, temperatureRatio)` (layer 1 above 0.3: (f-0.3)/0.7, layer 2 above 0.7: (f-0.7)/0.3, layer 3 above 0.9: (f-0.9)/0.1, else 0, f = 1 - ratio), `DotRatio(spawnDistance, levelDistance)`.
- `Gamelab.UI.HudModel`: holds the level definition, the smoothed speed ratio (0.15 lerp per `Update` call, as Src, frame-rate dependent on purpose for parity) and the temperature ratio. `Update(distance, actualSpeed, temperature, maxTemperature, maxSpeed)` computes train marker fraction, needle degrees and frost opacities. No clock of its own, so pause (timeScale 0) cannot stall or advance anything.

Runtime (`Gamelab.UI.Runtime`, PlayMode tests):
- `Hud.uxml`, `Hud.uss`: layout in 1920x1080 canvas units from the Gum files (numbers listed in the task 3 brief).
- `HudView`: MonoBehaviour on a `UIDocument`, `Bind(HudModel, PanelSettings)`, `Refresh()`, rebuilds on enable like `HubOverlayView`.
- `HudController`: owns model, view and a `UiPanel.Create()` panel. `Bind(TrainState state, LevelDefinition level, float maxSpeed)`, `SetLevel(LevelDefinition)`, `Update` reads state and refreshes. Convenience `Bind(TrainStateRuntime, LevelRuntime)` reads `TrainStateRuntime.State` and `LevelRuntime.Definition`. Uses no time at all, so it runs unchanged while paused. Sorting order is below the menus.

Art: `GaugeDistance`, `GaugeHand`, `spr_hud_train_marker`, `spr_hud_goal_x`, `spr_hud_enemy`, `FrostScreen1..3` into `Assets/Resources/UI/Art/` (the B2.1 importer rule applies by path).

## Tasks (TDD, tests, commit, then task review)

1. Core: `HudMath`, `HudModel`, EditMode tests with script-derived goldens.
2. Art import: copy the eight files, extend `UiSpriteImportTests` and a PlayMode load test.
3. `Hud.uxml`, `Hud.uss`, `HudView` with PlayMode tests: layout numbers from `resolvedStyle` (tolerance 3), needle rotation, marker position follows ratio, one dot per spawn event, frost opacity, texts.
4. `HudController` with PlayMode tests: state to view flow with a real `TrainState`, level change rebuilds dots, works with `Time.timeScale = 0`, convenience overload with `TrainStateRuntime` and `LevelRuntime`.
5. CONVENTIONS section, stale deferred lines fixed, then the lead runs both full suites.

Final: whole-branch review (most capable model), one fix wave, one scoped re-review. Verify EditMode and PlayMode, `git diff 4554310 -- Src/` empty, `dotnet build Src/Gamelab.csproj`, no stray `.meta`.
